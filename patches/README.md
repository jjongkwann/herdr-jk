# Local patches for installed mods

Fixes made to installed copies of mods and tools this repo doesn't own: Shepherdr's mods, pr-flow, and the like. An update (`shepherdr update`, a mod reinstall) overwrites the installed files, so each fix is kept here as a patch. After an update, `scripts/patches.mjs` shows which fixes the update removed, and the Assistant applies again the ones upstream still lacks.

- Each patch is a unified diff with paths relative to the install root, `~/.config/herdr-app` (`mods/chat/record.ts`), one file per fix, grouped by owner and by the version it was made against (`shepherdr/3.1.44/…`).
- Lines above the first `diff --git` are its header: `Subject`, `Owner` and `Versions`, the range of the owner's installed version it is for (`>=3.1.5 <3.1.29`, `>=3.1.34`, or `*`). The script reads Shepherdr's version from `bin/shepherdr` under the root. Owners with no version (the forks) use `*`. A patch for files outside `~/.config/herdr-app` adds `Root`, the install root its paths are relative to (`Root: ~/.config/herdr-core` for Shepherdr's templates); `--root <Root>=<dir>` points it at a scratch copy (`--root ~/.config/herdr-core=/tmp/core`), as `--root <dir>` does for the default root.
- Code changes to the person's own forks (pr-flow, herdr-sim, files-plus) belong in those repos. Only changes made at install time are patches here.

## After an update

The Assistant does this after `shepherdr update`, a mod reinstall, or on finding that something it installed was updated:

1. In this repo, run `node scripts/patches.mjs status`. It checks `~/.config/herdr-app`; use `--root <dir>` for another root. It exits 1 while a patch is missing or conflicts.
2. Act on each state:
   - **applied**: the install has it, nothing to do.
   - **missing**: the patch applies cleanly. Read the owner's changelog for an equivalent fix first. If there is none, run `node scripts/patches.mjs apply <name>` (or `apply` with no name for every missing patch). `apply` never touches a patch that conflicts.
   - **conflict**: upstream changed those lines, or the update replaced some of a patch's files and kept the others. In the second case rebuild the patched files from the new source first, as under [After the update to Shepherdr 3.1.44](#after-the-update-to-shepherdr-3144). Otherwise read the new upstream file. If it has an equivalent fix, record that in the Upstream column and delete the patch. If not, make the fix again against the new version as a new patch in a folder for that version, and end the old patch's `Versions` range before it.
   - **not applicable**: the patch is for another version of its owner. If it is for an older version, its Upstream column says whether the new version covers it. If the new version does, delete the patch. If it doesn't, port it as above.
   - **target missing**: the file moved or the mod is gone. Find where it went, and port the patch or delete it.
3. After applying, run `~/.config/herdr-app/bin/sync-shared --check`, `shepherdr doctor` (an update holds the sync to other machines until doctor finds the install whole) and `herdr-app check mods/<mod>` for each mod you patched. Saving a mod file hot-reloads every copy of that mod, so let `apply` write each file once instead of editing it by hand several times.
4. Update the table above and commit.

To make a new patch, copy the upstream files at their install paths into a scratch git repo and commit them. Copy the fixed files over them, then save `git diff`, with a header on top, as `patches/<owner>/<version>/<name>.patch`. Then check that `status` reports it as applied on the install.

## After the update to Shepherdr 3.1.44

The 13 patches were ported on 2026-11-19 by cherry-picking a commit per patch from a 3.1.41 tree onto 3.1.44. Only `windows-tasks` conflicted, on one line in `cli.py`. 3.1.44 now installs herdr-task on another machine with `sh -c 'chmod +x "$1" && mv -f "$1" "$2"'`, which already goes through `sh` as the patch's line did, so the patch no longer changes that line. No patch's other lines changed, and 3.1.44 covers none of them. `layouts/omarchy.json`, `MODS` in `scripts/win-pc/core.mjs` and the omarchy-tabs copies needed no change: 3.1.44 removed no mod and didn't touch those shared files.

`shepherdr update` replaces the patched files Shepherdr changed and keeps the others, so right after it `status` reports conflicts, and the update prints `NOT DONE: the install isn't whole`. Run these from this repo. They build the patched files in a temporary folder and move in only the ones that differ, so each mod file is saved once:

```sh
git -C ~/workspace/40_LIBRARY/shepherdr merge --ff-only v3.1.44
shepherdr update --source ~/workspace/40_LIBRARY/shepherdr --keys keep --yes

B=$HOME SRC=$HOME/workspace/40_LIBRARY/shepherdr ST=$(mktemp -d)
mkdir -p "$ST/app/bin" "$ST/core" "$ST/share"; cp "$SRC/bin/shepherdr" "$ST/app/bin/"
for p in patches/shepherdr/3.1.44/*.patch; do
  case $p in *worker-template-firefox*) d=$ST/core;; *windows-chat-service*) d=$ST/share;; *) d=$ST/app;; esac
  sed -n 's#^+++ b/##p' "$p" | while read -r f; do
    case $f in */compat.py) continue;; */omarchy-tabs/coordinator.js) s=lib/coordinator.js;; *) s=$f;; esac
    mkdir -p "$d/$(dirname "$f")"; cp -p "$SRC/$s" "$d/$f"
  done
done
node scripts/patches.mjs apply --root "$ST/app" --root "$HOME/.config/herdr-core=$ST/core" --root "$HOME/.local/share/shepherdr=$ST/share" shepherdr/3.1.44
put() { (cd "$1" && find . -type f) | while read -r f; do cmp -s "$1/$f" "$2/$f" || mv -f "$1/$f" "$2/$f"; done; }
put "$ST/app" "$B/.config/herdr-app"; put "$ST/core" "$B/.config/herdr-core"; put "$ST/share" "$B/.local/share/shepherdr"
rm -rf "$ST"
rm -f "$B"/.config/herdr-app/{bin/herdr-secret,core/agents.js,core/chat-log.js,lib/coordinator.js,lib/COPIES}.new "$B/.config/herdr-core/templates/worker.md.new" "$B/.local/share/shepherdr/core/chat-log.js.new"
python3 -c 'import json,sys; p=sys.argv[1]; k=json.load(open(p)); k["global"].pop("ctrl-k",None); open(p,"w").write(json.dumps(k,indent=2,ensure_ascii=False)+"\n")' "$B/.config/herdr-app/keys.json"

node scripts/patches.mjs status
~/.config/herdr-app/bin/sync-shared --check
shepherdr doctor
```

- The `python3` line removes the global `"ctrl-k": "mod.open:jump"` the update puts back (HJK-17: Ctrl+K stays the terminal's). The `ctrl-k` entries under `terminal` and `layout:shepherdr` stay.
- `shepherdr doctor` ends the hold the update puts on the sync to other machines. After it, run `~/.config/herdr-app/mods/tasks/bin/herdr-task machines sync win-pc`.
