# Local patches for installed mods

Fixes made to installed copies of mods and tools this repo doesn't own: Shepherdr's mods, pr-flow, and the like. An update (`shepherdr update`, a mod reinstall) overwrites the installed files, so each fix is kept here as a patch. After an update, `scripts/patches.mjs` shows which fixes the update removed, and the Assistant applies again the ones upstream still lacks.

- Each patch is a unified diff with paths relative to the install root, `~/.config/herdr-app` (`mods/chat/record.ts`), one file per fix, grouped by owner and by the version it was made against (`shepherdr/3.1.34/…`).
- Lines above the first `diff --git` are its header: `Subject`, `Owner` and `Versions`, the range of the owner's installed version it is for (`>=3.1.5 <3.1.29`, `>=3.1.34`, or `*`). The script reads Shepherdr's version from `bin/shepherdr` under the root. Owners with no version (the forks) use `*`.
- Code changes to the person's own forks (pr-flow, herdr-sim, files-plus) belong in those repos. Only changes made at install time are patches here.

## Checked, nothing to patch

- **The rest of Shepherdr 3.1.5.** Its `lib/`, `bin/`, `core/` and other mod files under `~/.config/herdr-app`, what it installs under `~/.local/share/shepherdr` (its service and helper copies; not the built web app in `web/dist`, which the source tree doesn't hold), and the templates in `~/.config/herdr-core/templates` match the 3.1.5 source (commit 5ca5b07). The only differences are the edits patched above and the `gpui-kit.d.ts` and `jsconfig.json` type stubs Herdr writes into each mod. `~/.local/bin`'s helpers are links into `~/.config/herdr-app`.
- **Herdr's built-in mods** (tabs, spaces, files, pane, …, Herdr 0.1.15). Each of the 333 files Herdr's `installed.json` lists for them matches, byte for byte, the copy embedded in `/Applications/Herdr.app/Contents/MacOS/Herdr`. Herdr also moves an edited shipped mod to `<name>-edited` at its next start and restores its own copy, so a built-in can't keep a local edit. To change one, clone it (Duplicate mod) instead of patching it.
- **files-plus** is the same as `herdr-files-plus` `main`. **herdr-sim** and **herdr-sim-screen** are the same as `herdr-sim` `pin-serve-sim`, apart from the copied `LICENSE` and the simulator's own `panel-*.jpg` frames. pr-flow has the `LICENSE` copy and the `mod.json` patch above.
- **Fixed upstream, no patch:** under 3.1.5, `launch.py`'s low-priority wrapper printed an `oom_score_adj` error on macOS (`echo 500 > /proc/self/oom_score_adj` before its `2>/dev/null`). 3.1.29 wraps it in `{ …; } 2>/dev/null` (SHEP-170), so 3.1.34 has the fix.

## After an update

The Assistant does this after `shepherdr update`, a mod reinstall, or on finding that something it installed was updated:

1. In this repo, run `node scripts/patches.mjs status`. It checks `~/.config/herdr-app`; use `--root <dir>` for another root. It exits 1 while a patch is missing or conflicts.
2. Act on each state:
   - **applied**: the install has it, nothing to do.
   - **missing**: the patch applies cleanly. Read the owner's changelog for an equivalent fix first. If there is none, run `node scripts/patches.mjs apply <name>` (or `apply` with no name for every missing patch). `apply` never touches a patch that conflicts.
   - **conflict**: upstream changed those lines. Read the new upstream file. If it has an equivalent fix, record that in the Upstream column and delete the patch. If not, make the fix again against the new version as a new patch in a folder for that version, and end the old patch's `Versions` range before it.
   - **not applicable**: the patch is for another version of its owner. If it is for an older version, its Upstream column says whether the new version covers it. If the new version does, delete the patch. If it doesn't, port it as above.
   - **target missing**: the file moved or the mod is gone. Find where it went, and port the patch or delete it.
3. After applying, run `~/.config/herdr-app/bin/sync-shared --check` and `herdr-app check mods/<mod>` for each mod you patched. Saving a mod file hot-reloads every copy of that mod, so let `apply` write each file once instead of editing it by hand several times.
4. Update the table above and commit.

To make a new patch, copy the upstream files at their install paths into a scratch git repo and commit them. Copy the fixed files over them, then save `git diff`, with a header on top, as `patches/<owner>/<version>/<name>.patch`. Then check that `status` reports it as applied on the install.

## After the update to Shepherdr 3.1.34

- Run `node scripts/patches.mjs apply`. The four `shepherdr/3.1.34/*` patches apply cleanly to a tree laid out from 3.1.34 (checked on a scratch copy). The `shepherdr/3.1.5/*` patches then show as not applicable. Delete that folder: 3.1.34 covers or makes obsolete each of them except the model families, which `shepherdr/3.1.34/claude-model-families` carries forward.
- Chat dictation in 3.1.34 sends the recording to ElevenLabs Scribe (the voice call's key, in Settings › Secrets) instead of running whisper.cpp locally. The local whisper model fix therefore has no target. This repo's `omarchy-voice` still uses whisper.cpp and is unaffected.
- After applying, run one live check with an agy task: `herdr-task add … --agent agy`, then `start`. It should start without the trust dialog and begin on its brief. If agy exits at launch, the task should show `Couldn't start: <agy's error>` within about a minute.
- What these patches don't cover for agy: Shepherdr records no session id for an agy agent, so `resume` and `switch` start a fresh agy with a handoff (through `-i`, so it starts). Recovery after a crash (`revive.py`) brings back only claude and codex agents and leaves an agy worker at its shell, as before. agy has no hook that puts its permission questions on the chat's card, so on a machine whose agy settings ask before running tools, a worker waits at agy's own prompt.
